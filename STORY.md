# Why these three habits became one loop

Improvement work commonly fails at one of three seams.

First, a team responds to friction by adding another store, command, wrapper, or dashboard. The new thing works briefly, but no one knows which copy owns the truth. KISS makes the existing ownership map visible and prefers consolidation before construction.

Second, a task can be technically complete while its nearest consumer, configuration edge, or proof instrument is still broken. ABCD checks those immediate joints, but keeps the scan bounded so "go further" does not become unlimited scope.

Third, a useful correction can disappear into chat. DBNT gives the lesson a durable form, looks for recurrence, and proposes the smallest mechanism that prevents the class of failure.

Running these as separate optional rituals left gaps between them. An ABCD-only pass could fix an adjacent symptom while missing a duplicate authority. A DBNT-only pass could faithfully document a pattern while the new implementation created fresh sprawl. A KISS-only pass could simplify the architecture without preserving the lesson.

The combined loop closes those seams in order: inspect the adjacent joints, capture or compound the learning, inventory and consolidate, recheck the resulting architecture, then prove the path that a consumer will use.

This skill emerged from a production multi-agent system where each habit existed as a separate instruction. The gaps between them kept recurring. Combining them into one ordered loop eliminated most of the recurring failure class: work that finished cleanly but left the next handoff broken, undocumented, or duplicated.
